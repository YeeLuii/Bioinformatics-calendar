# 使用指南

## 1. 组织一周的分析工作

1. 按 README 启动空工作区，点击“新建项目”。填写名称、研究内容、当前进度、采用版本、适用范围与待完成事项。
2. 填写本机目录；需要服务器时再填写远程目录与 SSH 别名。目录可以留空，以后补充。
3. 新项目卡片出现在“待安排”。拖到四象限上；右侧更紧迫，上方更重要。单个象限内也可以自由摆放。
4. 点击卡片 `···` 可以通过菜单调整位置。新建文件夹后，把同一课题的项目、会话或目录卡片拖进去。
5. 点击计划本中的日期，再点击添加待办，填写具体要完成的事并关联卡片。
6. 完成后勾选待办。需要进入项目时，点击待办文字，在编辑面板选择“打开关联卡片”。

建议把项目 `todo` 写成该项目下一阶段要完成的工作，把日历待办拆成有日期的具体动作。例如项目待办是“完成差异表达结果复核”，周二的日历待办是“检查两个离群样本及其测序质量”。

桌面文件夹是视觉分组，不对应磁盘目录，不改变 Codex 项目归属。目前只支持一层文件夹。卡片允许重叠；通过拖动或菜单重新安排，不会自动重排用户布局。

文件夹展示见 [演示截图](https://github.com/YeeLuii/Bioinformatics-calendar/blob/main/docs/screenshots/folder.png)。

## 2. 查看任务状态与结果

点击项目卡片，详情中的“项目概述”显示进度、版本、结果适用范围与待办。“项目地址”显示目录及关联会话。没有服务器地址的项目不会显示服务器入口。

点击“查看结果”进入项目资料视图。结果包可以登记为文章结果、探索性结果、中间文件、日志、输入代码或待复核。点击结果包查看范围、版本和来源依据。接入文件索引后，可在统一清单查询具体文件并预览部分文本格式。

新建的普通项目还没有结果包。可以先在概述中记录结果说明和目录，随后按 [数据模型](DATA_MODEL.md) 接入摘要或文件索引。`examples/create_demo.py` 展示了最小结果包生成方式。

工作台本身不登录服务器读取任务状态，也不运行科研分析。`status` 由分析人员、Agent 或外部适配器维护；请写明“计算完成、结果未复核”“已复核 v2”等具体状态。服务器目录显示“已登记地址”不代表已验证可访问。

## 3. 返回分析会话

在项目详情点击“管理关联”，从已有会话目录选择，或粘贴已有会话的 UUID / `codex://threads/...` 链接。保存后点击“打开会话”，由操作系统调用 Codex 客户端。

会话入口只负责跳转；继续对话、重命名和归档真实会话由 Codex 处理。演示工作区没有任何真实会话 UUID。将自己的会话关联到个人工作区，不要提交到公共仓库。

## 4. 使用 Agent 管理项目

先生成客户端配置并重载，详见 [接口文档](API.md)。之后可以按下面的方式提出请求：

- “列出研究项目，分别说明当前进度、采用版本和待完成事项。”
- “新建一个蛋白结构比较项目，目录为我指定的本地路径，下一步先整理输入序列。”
- “把 RNA-seq 项目的进度改为‘差异分析完成，等待复核’，其他字段保持原值。”
- “把结束的预实验归档，保留文件和原来的桌面位置。”
- “恢复刚才归档的预实验，检查其会话关联是否仍然存在。”

Agent 应先读取项目与 revision，再提交修改。发生冲突后重新读取和比较，不能盲目覆盖。MCP 新建项目会出现在左侧项目列表；若个人桌面已经保存过，进入详情点击“加入桌面”即可添加卡片。

## 5. Python 调用示例

网页运行时：

```bash
python examples/http_client.py --base http://127.0.0.1:8828 list
python examples/http_client.py --base http://127.0.0.1:8828 create-example
python examples/http_client.py --base http://127.0.0.1:8828 summary --project-id api-example
```

第二条命令会创建 `api-example`。重复运行会因 ID 已存在而返回错误，不覆盖项目。完整源码可作为接入现有分析脚本的起点；业务系统也可在调用 `desktop_runtime.configure()` 后直接导入 `desktop_services.execute()`。

## 6. 保存与迁移

桌面和计划本自动保存在工作区 data 目录中的 `desktop_board_state.json`，前一次保存为 `desktop_board_state.previous.json`。“备份安排”下载的是卡片和日程，不包含完整项目资料。

完整迁移使用 `desktop_manage.py pack`。程序与个人工作区分开部署时，只更新代码目录即可保留日程和项目；升级前仍建议备份工作区。恢复备份时先停止对应服务，并保留当前文件副本，避免覆盖刚发生的修改。

## 7. 常见问题

| 现象 | 处理 |
|---|---|
| 端口被占用 | 修改 workspace.json 的 port，或启动时增加 `--port 8833` |
| 修改提示版本冲突 | 刷新页面或重新读取 revision，确认其他客户端的修改 |
| 本机目录无法打开 | 核对路径是否存在、是否需要迁移映射；不要把服务器路径填成本机路径 |
| 会话无法打开 | 确认本机安装 Codex、协议关联有效、当前账号可访问该会话 |
| 统一清单不能点击 | 当前工作区未接入逐文件索引；项目与日程功能仍可使用 |
| 新的计算没有自动显示 | 手动更新项目，或配置自己的摘要/索引适配器；核心没有默认扫描器 |
| 想同步团队成员 | 当前是本机单用户应用；可分享摘要或迁移副本，不支持多人远程实时协作 |
