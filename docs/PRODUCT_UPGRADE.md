# AI4S 科研项目管理升级要求与验收清单

评估日期：2026-11-25。本文是本轮升级的产品要求，完成情况以 `UPGRADE_QA.md` 的实际验证记录为准。写入要求不表示功能已交付。

产品服务于同时维护多个分析项目的科研人员。用户应能快速回答：项目在做什么、进度来自何时的记录、当前采用哪份结果、下一步如何安排，以及从哪里返回目录或分析会话。

## 使用路径

1. 用户或 Agent 登记一个已有研究项目，保存研究问题、来源、目录与关联会话。
2. 将下一步拆为任务，安排开始和结束日期；任务归属项目，桌面卡片只是该项目或资料的快捷方式。
3. 在四象限、今天、本周、任务列表和甘特图之间切换，查看同一批任务。
4. 运行或复核后更新进度，注明观察时间、来源和结果采用情况。
5. 需要汇报时导出摘要和计划；换电脑时迁移元数据并映射目录，研究文件继续保留在原处。

## 不变量

- 核心服务保持 Python 标准库与浏览器原生实现，不要求数据库服务、前端构建或聊天 SDK。
- 只管理元数据，不移动、删除或修改科研数据，不结束科研进程，不自动向会话发送消息。
- 保留旧项目 ID、会话关联、地址、卡片位置、文件夹关系和日程。新增字段采用兼容默认值；导入、升级失败不能留下半份状态。
- 写入保留 revision 冲突检查、跨进程锁和原子保存。不得为了简化 Agent 调用而允许过期快照覆盖新修改。
- “程序执行成功”“结果已复核”“可以用于文章”是不同含义。未接入或无法确认的状态显示未知，不推断成功或失败。
- 所有验证使用合成临时工作区。公开截图、测试和文档不含真实研究项目、会话 ID 或私人地址。

## 验收要求

| 编号 | 要求 | 可验证的完成条件 |
|---|---|---|
| R01 | 来源和时间可信 | 项目可保存并显示来源、资料整理时间、实际观察时间、复核时间；整理旧资料不会自动把观察时间改成现在；`reviewed` 不再被直接显示成文件指纹一致 |
| R02 | 科研状态分层 | 可分别登记研究阶段、计算状态和结果采用情况；运行成功不会自动把探索结果改为文章结果；没有状态证据时可明确标为待核实 |
| R03 | Agent 可安排工作 | HTTP/MCP 共用业务逻辑和 Schema；可读取、新建、更新、完成待办，组织卡片和单层文件夹；只改目标项；冲突返回可理解的错误 |
| R04 | 任务直接归属项目 | 任务支持稳定 `project_id`；删除、移除或重排桌面卡片后，任务与项目的联系仍保留；兼容仅关联卡片的旧待办 |
| R05 | 可用的甘特图 | 显示项目分组的任务起止日期与时间尺度、今天线、进度或完成状态、里程碑和依赖；可在任务详情或拖动方式改期；校验结束早于开始、自依赖和循环依赖；计划本和甘特图读取同一份任务 |
| R06 | 日常查看与搜索 | 提供今天、本周、待复核入口；搜索可找到已放在象限或文件夹内的项目、卡片、会话和地址；结果可返回详情或导航；自由摆放与自动排列互不丢失用户布局 |
| R07 | 修改历史和撤销 | 用户能查看一次修改的对象、时间和变化；至少支持项目与日程/卡片修改的按次撤销；如果后续变更冲突，不盲目恢复整个旧快照；撤销保留无关后续修改 |
| R08 | 重复工作与导出 | 支持至少每日、每周、每月的重复待办；完成一次不会无限提前生成任务；月末、闰年、重复完成、取消完成有明确行为；支持日历文件导出并说明关闭网页后的提醒边界 |
| R09 | 结果版本独立 | 一个项目可管理多个结果包及各自采用版本、用途、来源和待复核事项；改变其中一个结果包不改其他结果包；原有结果索引仍能浏览 |
| R10 | 诊断与迁移 | 提供工作区诊断，区分本地目录存在/缺失与服务器未核实；路径映射可以预览和保存；不重写研究目录；迁移后稳定 ID 与原引用保留，接口说明迁移边界 |
| R11 | 升级保持数据 | 对旧结构合成工作区执行读写、打包还原和新功能操作，核验项目/卡片/日程/链接不丢失；生产切换前有备份与可恢复记录，切换后核对真实元数据保留 |
| R12 | 产品交付完整 | 新功能具备使用示例、接口契约、演示资料、真实浏览器检查与测试；Windows/Linux 已有兼容范围保持；端口、启停、MCP 配置处理不引入手写 TOML 或自动安装解释器 |

## 甘特图的具体行为

- 任务以日期为基本单位，默认不要求具体时刻。单日任务起止为同一天；里程碑为单日节点。
- 保留用户设置的任务日期。依赖关系应提示前置任务尚未完成或日期冲突，不能静默移动整条计划。
- 自依赖和循环依赖应拒绝保存；依赖对象删除的行为必须有明确约束或清理提示。
- 任务数量增加时，提供项目筛选、时间尺度或滚动，而不是把全部任务压缩成不可点击的小条。
- 进度条代表登记的任务进展。科研完成程度不能仅凭已勾选待办比例自动推断。
- 建议保留键盘或表单改期入口，避免甘特图只能用精细拖拽操作。

## 重复任务与撤销的边界

重复任务宜在完成本次后生成一个后续实例，并用来源 ID 避免重复生成。取消完成不能悄悄删除用户已经修改的后续任务。月末规则应明确，例如按上一实例日期截到下个月有效日，或保持原始日号锚点；实现和文档必须一致。

撤销的最小可靠单位是一次业务操作。只恢复本次操作改过、并且之后未被改写的字段或条目；存在冲突时提示用户检查，不覆盖后续工作。不能用“有上一份 JSON 文件”替代可验证的撤销体验。

## 交付顺序

1. 先建立任务模型、稳定单项接口、可信状态字段和兼容迁移；这些决定所有视图能否复用数据。
2. 实现任务编辑、甘特图、今天/本周/待复核、统一搜索和桌面排列。
3. 接入历史撤销、重复任务、结果版本、诊断迁移和导出，并同步文档与合成演示。
4. 完成独立验收、生产数据备份和服务切换。测试通过不替代浏览器交互和生产保留验证。

## 验证方法

自动检查覆盖旧数据兼容、业务错误、版本冲突、重复与撤销边界、结果版本隔离、导出以及真实 stdio MCP。浏览器检查覆盖桌面和窄屏渲染、甘特图实际编辑、视图间一致性、搜索后导航、错误提示和刷新保留。

最小用户旅程：创建一个含两个结果版本的合成项目，新增三个相依任务和一个里程碑，安排重复复核；在甘特图改期；回到计划本查看；移除项目快捷方式；确认任务仍归属项目；更新结果采用情况；撤销一次独立修改；导出日历；打包迁移后重新打开。

最终记录必须区分：已通过、失败、待实现、尚未验证。任何一项未达到要求，都应保持本轮目标未完成，并列出下一步修订。
