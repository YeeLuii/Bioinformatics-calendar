# 文件夹内整理

打开桌面文件夹，可以按标题或地址搜索、按卡片类型筛选。超过 12 张可见卡片时默认使用列表视图，随时可以切换为卡片视图。

- 拖动到其他卡片的前后，或点击置顶、上移、下移，顺序会自动保存。
- “按名称整理”使用中文名称及自然数字顺序；“按类型整理”依次放置研究项目、会话和目录，同类按名称排序。这两个按钮会保存新顺序。
- 勾选多张卡片，选择已有文件夹、待安排区，或“新建桌面文件夹…”并填写名称，再点“移入”。例如可以把图表相关卡片移到“论文·图表”。
- 搜索或类型筛选期间暂停排序，以免改变未显示的卡片。批量移动仅处理明确选中的卡片；改变筛选会清除选择。
- 整理后可在“修改记录”撤销；如果其他客户端已经修改相同字段，系统会提示冲突，需要刷新后重新检查。

桌面文件夹目前是一层视觉分组，不是磁盘目录，也不改变 Codex 中真实会话的归属。升级不会自动调整已有文件夹的顺序。

## Agent 接口与保存规则

1.2.1 的 `card_create` / `card_update` 支持可选 `order` 整数（0–1000000）。它仅决定同一文件夹内的展示顺序，较小值在前；未设置的卡片排在已有排序之后；同值按 `cards` 数组顺序。排序不改变 `target`、项目关联、任务或科研文件。读取旧工作区不生成排序值，也不写入文件。

Agent 先调用 `cards_list` 获取 revision 和文件夹 ID，再调用 `card_update`，例如：

```json
{"card_id":"review-card","patch":{"order":0},"expected_revision":12}
```

单次更新不自动重排其他卡片。公开 MCP 的逐卡片更新每次都应使用上一次返回的 revision，多个调用不是一次原子操作。要完成一次性多卡片重排，可以读取完整 `/api/board-state`，保留其他卡片和 todos，将目标文件夹的顺序依次设为 0、1、2，再按 [API 授权与 revision 规则](API.md)通过网页内部 `POST /api/board-state` 一次提交完整快照。不得使用旧 revision 强行覆盖。

通过 `card_update` 更换 `folder` 且没有显式提供 order 时会清除旧排序，新位置排在已有排序之后。网页批量移动会保持选中项的相对顺序，放在目标文件夹末尾；也支持在一次提交中创建桌面文件夹并移入选中项。所有修改复用原来的 revision、原子保存和修改记录，可按字段冲突检查撤销。
